# KDL 2.0 Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `orocos_kdl` 2.0.0. It has a C++17 baseline, measured C++ test coverage with a CI gate, a deliberate inline/out-of-line split for every frame function, and one coherent equality model: exact `operator==`, magnitude-scaled `Equal`. The `.inl` files and configuration macros are gone, and all headers are `.hpp` in an `include/kdl/` layout.

**Architecture:** Twelve sequential PRs.
- Tasks 1–3 lay the groundwork: C++17, CMake hygiene, coverage tooling.
- Task 4 pins the behaviour of every frame function with tests *before* Tasks 5–8 move and change those functions.
- Tasks 9–11 are cleanup and layout; Task 12 bumps the version.

Breaking changes are allowed (major release) and each one is recorded in `orocos_kdl/MIGRATING.md`. Performance-relevant changes are measured with the benchmark from Task 6. Coverage may not drop below the ratcheted floor from Task 3 on.

**Tech Stack:** C++17, CMake ≥ 3.12, Eigen3, CppUnit, gcov + lcov 2.0 (GCC-only coverage), clang-tidy-18, pybind11 (PyKDL), GitHub Actions (ubuntu-22.04/24.04 × gcc/clang), ament/colcon (optional path), Debian packaging in `orocos_kdl/debian/`.

**Spec:** *Background and decisions* below, plus the per-function table `docs/superpowers/plans/2026-11-11-kdl-2.0-inline-decisions.md` (441 functions).

## Global Constraints

- Version `2.0.0` (`KDL_VERSION`, both `package.xml`, `python_orocos_kdl` `project(VERSION)`); `SOVERSION 2.0`. Set in Task 12, not before.
- Library **and consumers** need C++17. Public headers use `inline constexpr` (Task 8).
- Every API/ABI break is listed in `orocos_kdl/MIGRATING.md` by the task that introduces it, with the replacement and, where possible, a `sed` one-liner.
- Numerical results change only where D3/D4/D6 say so. A test whose expectation changes must be named and justified in the commit body.
- Performance: no benchmark case (V7) may regress by more than 5 % against the Task 6 baseline. After Task 7, `F = F*G` latency must improve ≥ 2×.
- Coverage (V8, from Task 3): line and function coverage never fall below the floors in `orocos_kdl/tests/coverage.json`. When a task raises coverage, it raises the floors to the new value rounded down to 0.1. A task may lower a floor only when it deletes covered code, and must say so in the commit body.
- Leave the numerical algorithms in `frames.cpp` alone (scaled `Norm`, Shepperd quaternion extraction, atan2-based Euler angles), except for the D4 threshold fix and the D1 relocation of functions.
- Commit subjects use `(KDL) …`. One PR per task. Every task passes V1, V3, V4 and V6 before its commit; V8 from Task 3 on; V7 from Task 6 on.

## Background and decisions

### D1 — Inline only where it pays; decided per function

Every function in `frames.inl`, `framevel.inl` and `frameacc.inl`, the `IMETHOD` definitions in `framevel.hpp`, and the functions in `frames.cpp` has a decision in the companion table: **264 inline, 155 out-of-line, 22 removed**. The rules come from measurements (GCC 13.3, `-O3 -DNDEBUG`, `master` b7f433b):

| Measurement | Inline | Out-of-line | Conclusion |
|---|---|---|---|
| `F = F*G` (dependent chain, the FK loop shape) | 3.7 ns | 11.5 ns | `Rotation*Rotation` (currently in `frames.cpp`) must be inline: 3.1× |
| `C[i] = A[i]*B[i]` (throughput) | 7.9 ns | 9.7 ns | same, 1.2× |
| `v = v + d` (`Vector`) | 0.53 ns | 4.3 ns | small arithmetic must be inline: 8× |
| `Rotation::RotZ` (full matrix consumed) | 9.6 ns | 11.1 ns | sin/cos dominate; +1.4 ns ≈ 4 % of a 7-DOF FK per joint |
| `ChainFkSolverPos_recursive`, 7 DOF | — | 263 ns | reference |

Rules:
- **Inline:** trivial members, including the exact `operator==`/`!=` (K); double and `Vel` arithmetic (A); `Rotation*Rotation` (H).
- **Out-of-line:** transcendental math or rotation-parameterization conversions (T); tolerant `Equal` (E); `random`/`posrandom` (R); non-trivial `Acc` arithmetic, which no solver uses (X).
- **Removed:** member-wise copy constructors and assignments (C), so every frame type and `Rall1d`/`Rall2d` becomes trivially copyable.

There is no global inline switch any more. `KDL_INLINE`'s non-inline mode doesn't even compile today (`framevel.hpp:401: no matching function for call to 'posrandom(KDL::Vector&)'`). MSVC `__forceinline` (`IMETHOD`, `INLINE`) is dropped.

### D2 — No `.inl`; every header is `.hpp`

- **The `.inl` files are dissolved** per D1.
- **Renames:**
  - `utilities/*.h` → `.hpp`: `error`, `error_stack`, `hash_combine`, `rall1d`, `rall1d_io`, `rall2d`, `rall2d_io`, `rallNd`, `traits`, `utility`, `utility_io`.
  - `*.cxx` → `.cpp`: `utility`, `utility_io`, `error_stack`.
  - The generated `config.h` → `config.hpp`.
- **Each renamed installed header keeps a stub** at its old name for the 2.x series: an `#include` of the new name plus a `#warning`, the pattern ROS 2 used for tf2's `.h` → `.hpp` move.
- **Removed without a stub:** `kdl-config.h`, `utilities/scoped_ptr.hpp`, and `chainidsolver_vereshchagin.hpp`, whose removal was announced for 1.6.

### D3 — `Equal`: immutable epsilon, magnitude-scaled tolerance

Today a single mutable global `double epsilon = 1e-6` does two jobs: it is the comparison tolerance, and the degeneracy threshold for `Norm`, `Normalize`, `GetRotAngle` and `VelocityProfile_Trap`. Changing it races with every thread. The comparison is purely absolute, which gives these results on `master`:
- `Equal(1.0, 1.0, 0.0)` is **false**: the test is the strict `<`.
- Two values of 1e9 that differ by about 17 ulp are unequal.
- The array types use `<=` while the frame types use `<`.

Decision:
- **`epsilon` becomes immutable.** `inline constexpr double epsilon = 1e-6;`, and `PI`, `PI_2`, `PI_4`, `deg2rad` and `rad2deg` become `inline constexpr` too. The value stays 1e-6: KDL's IK solvers converge to 1e-5…1e-6 by default, and a tighter default would reject their correct results.
- **Scalar rule:** `Equal(a, b, eps)` ⇔ `a == b || (isfinite(a-b) && |a-b| <= eps * max(1, |a|, |b|))`. It is absolute up to magnitude 1 (rotations, unit vectors and angles are unchanged) and relative above 1. `eps = 0` means exact. `±inf` is equal only to itself. `NaN` is never equal.
- **Geometric types scale per physical quantity:** each component satisfies aᵢ == bᵢ or |aᵢ−bᵢ| ≤ eps·S, with S = max(1, largest finite |aᵢ|, |bᵢ| of that quantity).
  - `Frame` compares `p` and `M` separately, `Twist` compares `vel` and `rot` separately, and `Wrench` compares `force` and `torque` separately; the `Vel`/`Acc` types do the same per member.
  - `Rotation` entries are ≤ 1, so the rotation check is unchanged.
- **Arrays compare per element** with the scalar rule (`JntArray`, `JntArrayVel`, `JntArrayAcc`, `Jacobian`, `JntSpaceInertiaMatrix`), because their elements carry different units.
- **Degeneracy thresholds stay separate parameters** with `epsilon` as their default: `Normalize(eps)`, `GetRotAngle(axis, eps)`.

### D4 — `Norm()` has no epsilon

On `master`, `Vector(5e-7,0,0).Norm()` returns **0**, while `Vector(0,5e-7,0).Norm()` returns 5e-7: the cutoff is checked only in the x-dominant branch. `Vector2::Norm` has the same defect. The fix: `Norm()` loses `eps` and returns 0 only for the exact zero vector. The overflow-safe scaled algorithm stays. This also applies to `VectorVel`/`VectorAcc::Norm`.

### D5 — The index check stays enabled, as a plain `assert`

`KDL_INDEX_CHECK` / `FRAMES_CHECKI` become `assert(...)`. The index operators are inline, so the check follows the **consumer's** `NDEBUG`: debug builds catch out-of-range access, and release builds pay nothing. PyKDL already raises `IndexError`.

### D6 + D7 — `operator==` is exact, `Equal` is tolerant, hashing stays (decided: option b)

`KDL_USE_EQUAL` is removed. `operator==`/`!=` become **exact member-wise comparisons** for every frame type, inline per rule K, and `Equal(a, b, eps = epsilon)` is the tolerant comparison. This is the Eigen/`std` convention.
- It keeps the existing `std::hash` specializations (`e947516`) and PyKDL `__hash__` consistent with `==`, as the standard requires.
- Tolerant equality isn't transitive, so it can't back hashing or sorting.
- Behaviour change: code that relied on `a == b` meaning "within 1e-6" must call `Equal`.
- `+0.0 == -0.0`, so their hashes must match; `std::hash<double>` maps both to 0 in libstdc++ and libc++, and a test pins it.

### D8 — C++ test coverage, measured honestly and gated in CI

Coverage is measured with GCC `--coverage -O0 -fkeep-inline-functions` and lcov 2.0. `-fkeep-inline-functions` is required: without it, gcov only counts inline functions some test instantiated, so uncalled header code is invisible.

| Baseline, `master` b7f433b | Default gcov | With `-fkeep-inline-functions` |
|---|---|---|
| `orocos_kdl/src` total, lines | 62.7 % | **51.4 %** (3271/6359) |
| `orocos_kdl/src` total, functions | 55.7 % | **37.7 %** (489/1297) |
| `frames.inl`, functions | "95 % of lines" | **53 %** (100/188) |
| `framevel.inl`, functions | — | **10 %** (13/124) |
| `frameacc.inl`, functions | not listed | **0 %** (0/88) |

The code Tasks 5–8 move and change is mostly untested. Task 4 therefore brings every function in the frame core to 100 % function coverage before it is touched.

Other findings:
- **Nine dead test sources are deleted:** `rframestest`, `rallnumbertest` (commented out in CMake), and `iotest`, `jacobiandoubletests`, `jacobianframetests`, `jacobiantests`, `serialchaintest`, `toolkittest`, `zxxzxztest` (never built). All of them include headers that no longer exist (`kdl/test_macros.h`, `kdl/fvector.h`, `kdl/jacobianexpr.hpp`, `kdl/kdltk/toolkit.hpp`, …).
- **Whole subsystems are at 0 %:** every trajectory class, `path_line`/`path_composite`/`path_roundedcomposite`/`path_point`/`path_cyclic_closed`, every tree solver except inverse dynamics, `velocityprofile_rect`/`velocityprofile_spline`, and `jntarrayacc`. These go to a follow-up plan (Roadmap).
- **`ctest` must run in `<build>/tests`**, because `ENABLE_TESTING()` is called only in `tests/CMakeLists.txt`. From the build root it reports "No tests were found".

## Roadmap — separate plans

- **Tests for the 0 % subsystems listed in D8**, prioritized by downstream use: tree solvers, then paths/trajectories, then velocity profiles. Raise the floors as they land.

## Review Focus

1. **A vector whose largest component is tiny.** `Norm()` must be the same along every axis and never 0 for nonzero input. Pinned in Task 8 (`TestNormSmallVectors`).
2. **`Equal` at the edges:** `eps = 0`, `±inf`, `NaN`, and magnitudes above 1. Never loosened by infinities. Pinned in Task 8 (`TestEqualTolerance`).
3. **Mixed-unit compounds.** A large translation must not loosen the rotation comparison, and a large prismatic joint value must not loosen a revolute one. Pinned in Task 8 (`TestEqualPerQuantity`).
4. **`==` and `hash` agree,** including for `+0.0` vs `-0.0`, in C++ and Python. Pinned in Task 8 (`TestExactEqualityAndHash`, `testHashConsistentWithEq`).
5. **Coverage numbers that silently exclude code:** uncalled inline functions, or files renamed out of the extraction pattern. Pinned in Task 3 (the `-fkeep-inline-functions` check), Task 7 and Task 11 (`coverage.json` path updates checked by `coverage_check.py` failing on missing files).
