# KDL 2.0 — per-function inline decisions

Companion to `2026-11-11-kdl-2.0-modernization.md` (Task 7). Covers every function defined in `frames.inl`, `framevel.inl` and `frameacc.inl`, the `IMETHOD` definitions in `framevel.hpp`, and the functions in `frames.cpp`. Functions defined *inside* class bodies are already inline, keep that, and are not listed. The same goes for the scalar helpers in `utilities/utility.h` (`sqr`, `max`, `min`, `sign`, scalar `Equal`, the `::sin`/`::cos` forwarding wrappers).

Line numbers refer to `master` b7f433b; after Tasks 4–6, locate rows by signature. Benchmarks: GCC 13.3, `-O3 -DNDEBUG`, against `master`, on this machine. Reproduce them with the benchmark added in Task 6.

## Rules

| Code | Decision | Rule |
|---|---|---|
| K | inline | Trivial member: constructor, accessor, element access, `Zero`/`Identity`, unary minus, converting assignment, and the exact member-wise `operator==`/`!=` (D6). Cheaper than the call itself; inlining lets the compiler keep components in registers. |
| A | inline | Core value-type arithmetic (double and `Vel` types): 3–60 flops with no transcendental calls, used in solver inner loops. Measured: `Vector+Vector` 0.53 ns inline vs 4.3 ns out-of-line. |
| H | inline | Hot forward-kinematics operation, kept inline because measurement in context showed out-of-line costs too much. `Rotation*Rotation` (was out-of-line in `frames.cpp`), and `Rotation::RotX`/`RotY`/`RotZ`: Task 7 measured +6.4 ns per joint out-of-line inside `Joint::pose` (PLT call + store-forwarding stall on the returned `Rotation`), versus the +1.4 ns isolated estimate, so rule T is overridden for them. Measured: `F = F*G` 11.5 ns → 3.7 ns (3.1×), `C[i] = A[i]*B[i]` 9.7 → 7.9 ns. |
| C | remove | User-written copy constructor or assignment that only copies members. Delete it so the implicit one applies: the type becomes trivially copyable (memcpy in containers, passed in registers where the ABI allows). |
| T | out-of-line | Calls sin/cos/atan2/sqrt, directly or through another out-of-line function, or converts between rotation parameterizations. The math dominates the cost: measured `RotZ` 9.6 ns inline vs 11.1 ns out-of-line (+1.4 ns, ≈4 % of a 7-DOF FK per joint). |
| E | out-of-line | Tolerant `Equal` on compound types. Not an inner-loop operation, and the tolerance policy (D3, Task 8) then lives in one compiled place. |
| R | out-of-line | `random`/`posrandom` test helpers that call `rand()`. |
| X | out-of-line | Non-trivial `Acc` arithmetic. No KDL solver uses it, and bodies are large (`FrameAcc*FrameAcc` compiles to 686 bytes). |

**Totals:** 267 inline, 152 out-of-line, 22 removed (441 functions; 4 of the removals are in the `Rall` templates, listed at the end).

"Out-of-line" means: declaration stays in the `.hpp` (without `inline`); the definition moves to the matching `.cpp` (`frames.cpp`, `framevel.cpp`, `frameacc.cpp`). "Inline" means: the definition moves into the `.hpp`, after the class definitions, marked `inline`. A `remove` row means: delete both the declaration and the definition.
